## 2. `beta.4` 拦截与 `beta.5` 修复

`v1.0.0-beta.4` 完成了 Client 交易工作台、迁移 `0043`、身份 gateway 和数据库恢复演练，但没有被登记为 `current`。真实 Client 账号 smoke 在 `/api/credits/me` 发现 500：Credits 投影仍直接 join 已启用 FORCE RLS 的 `users` 表。发布 Gate 正确阻止了指针切换。

`v1.0.0-beta.5` 作为新的不可变版本修复，而不是修改 beta.4 tag：

1. Credits 只读取 `ai_credit_accounts` 和不可变 ledger；未建账户时返回真实零余额、`updatedAt=null`，不伪造 1970 时间。
2. 商业披露确认以 user ID advisory transaction lock 串行化，不再锁定 `users` 行。
3. 优盾充值订单直接使用已认证 session 的 `user.id` 与 `organizationId`；外键和会话身份继续承担完整性约束。
4. PostgreSQL 测试创建无 `users` 权限的 reader，证明 Client Credits 投影在 FORCE RLS 边界下可用。
5. 合同测试禁止上述 Client 路径重新引入 `FROM users`。

## 10. 交付后的配置顺序

1. 撤销曾暴露的临时 Resend Key，创建 domain-scoped Sending Key、Webhook secret 与最小 allowlist；保持 send=false 完成验签和 suppression。

5. 每个域分别保存 evidence、完成 checker 复核，再只重建需要读取新 env 的进程。
