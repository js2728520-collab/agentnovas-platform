构建共同约束：

- `RIVERTON_RELEASE_TAG=v1.0.0-beta.3`；
- `GIT_COMMIT_SHA=d6b60f2f977ffde06075028a274684c4e24332fe`；
- Web 镜像分别固定 audience 和正式 Host；
- Runtime 不传 audience/Host；
- 每张镜像构建后从 Docker 读取实际 image ID，再按仓库算法计算 aggregate artifact SHA-256。

`scripts/release/build-container-images.mjs` 仍缺少 `--file deploy/container/Dockerfile`，因此本次没有把该 helper 描述为可用；此遗留项需通过单独代码变更和合同测试修复。

## 5. 切换过程

1. 确认 `current` 为 `beta.2`、`previous` 为 `beta.1`，三端和 PostgreSQL healthy。
2. 在新目录解包精确源码，生成 `release-manifest.json` 和只含非敏感发布身份的 `release.env`。
3. 对比 `beta.2` 和 `beta.3` release 配置：除版本、commit 和 artifact SHA 外保持一致。
4. 使用同一个 Compose project 仅重建 Client、Operations、Maintenance 和 Notification Worker。
5. 通过 `--no-deps` 排除 PostgreSQL，并核对切换前后 PostgreSQL container ID 都是 `5c6bd8da85f1d8589775801c6a3cb397d682bc4062d87307133d28c3c2eeed33`。
