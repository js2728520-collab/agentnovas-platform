# ADR-0025：行情源选择的作用范围，与官方卡决策轮的关系

状态：Accepted

日期：2026-08-24

关联：ADR-0018（共享决策轮与按组合准入）、P-03、T2.4、`MARKET_SOURCE_BINDING_SPEC.md`

## 背景

PRD 6.2 写着「行情源可与用户交易账户一致，也可由用户独立选择；每个策略可以绑定不同数据源」。
T2.4a 已经实现了 provider-independent 的选择与解析合同，T2.4b-1 把解析结果不可变地固定到
部署上。

固定之后立刻暴露一个问题：ADR-0018 让同一张官方卡在同一根已收盘 K 线上**只判断一次**，
决策轮身份是 `(strategy_code, symbol, timeframe, candle_close_time)`——**不含数据源**。
如果两位订阅同一张卡的客户选了不同的源，那一轮就会拿 A 源的判断去解释 B 源的行情。

当前所有部署都走同一个公共源，所以这是潜在而非已发生的问题。但「以后再说」在这里不成立：
一旦第一个客户换源，错误是静默的——两个人看到同一段七阶段叙述，而它只对其中一个人成立。

## 决策

### 1. 官方策略卡统一使用平台指定的行情源

三张官方卡（`ai_conservative` / `ai_balanced` / `ai_aggressive`）是**平台自营策略**。
它们的数据源由平台选定，客户不能为官方卡指定自己的源。

理由不只是成本。ADR-0018 的核心是「同一张卡的所有订阅者看到同一份七阶段判断」；允许按客户
换源，就等于让同一张卡在同一根 K 线上产生多份互相矛盾的公开叙述。客户之间无法再互相印证，
而「可解释、可审计的决策过程」正是这个产品在卖的东西。

### 2. 客户的行情源选择作用于三处，都不共享决策轮

- **行情页展示**：客户看哪个源的报价与 K 线。
- **策略研发与回测**：研究阶段用哪个源取数，绑定固定进策略版本（同 DSL 换源必须重测）。
- **客户自己投稿的策略部署**：每个部署独立成轮。

这三处都不涉及共享决策轮，因此不与 ADR-0018 冲突。数据模型本身已经把这条边界固化了：
`strategy_decision_rounds.strategy_code` 有 `CHECK IN ('ai_conservative','ai_balanced','ai_aggressive')`，
共享轮**只可能**属于官方卡；自定义策略的周期 `decision_round_id` 为空，各自独立。

### 3. 绑定分叉守卫从过渡措施升级为常驻检查

T2.4b-1 的 `assertRoundBindingConsistency` 原本是「等 ADR-0018 改模型之前的临时防线」。
既然官方卡的源统一，它的含义变了：**同一张官方卡上出现两个不同的 source policy
fingerprint，说明有代码或数据违反了本 ADR**，Runtime 必须失败关闭而不是继续。

它现在是一条不变量检查，不是待办事项。`legacy_unpinned` 记录不参与判定——它们没有真实
解析结果，用全零 fingerprint 比对只会产生假冲突。

## 后果

- ADR-0018 的决策轮身份**不需要修改**，共享轮模型保持原样。
- **第 2 条里的「客户自己投稿的策略部署」已经是跑着的路径**（2026-08-24 更新）。本 ADR 写成
  时，0053 的 `strategy_deployments_official_binding_check` 要求现货部署必须有
  `platform_strategy_code`，客户自定义策略只能走永续而永续路由关闭，因此当时那条路径是空的。
  迁移 0087 按需求方确认放开了社区策略的现货模拟部署，客户投稿策略的跟单现在会真实产生
  决策周期与模拟成交。**本 ADR 的结论不变**——社区策略各自独立成轮，不进共享决策轮
  （`strategy_decision_rounds.strategy_code` 的 CHECK 仍只允许三张官方卡）。
- 官方卡的源变更是平台级操作：换源意味着所有订阅者的历史绑定与新绑定不同，必须走策略
  版本升级，而不是就地改配置。
- Client 的源选择 UI 必须清楚区分「行情页/研发用源」与「官方卡运行用源」，不能让客户以为
  自己改了官方卡的数据来源。
- 未来若产品要求官方卡支持按客户换源，那是一次 ADR-0018 的模型变更（决策轮身份加入
  fingerprint、AI 解释成本按源种类倍增），需要新 ADR，不能靠放宽本 ADR 的守卫实现。

## 不做

- 不因为「合同支持按策略绑定源」就推断官方卡也能按客户换源——合同的能力范围与产品的
  授权范围是两件事。
- 不放宽分叉守卫来「让功能先跑起来」。守卫报错意味着有数据违反了本 ADR，应该修数据或修
  写入路径。
