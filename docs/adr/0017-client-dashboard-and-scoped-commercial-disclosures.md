# ADR-0017: 客户交易总览与作用域化商业披露

状态：Accepted

日期：2026-08-22

## 背景

Client 根路径同时承担公开营销入口和登录后的工作台入口，导致客户点击 Logo、登录默认跳转和菜单返回首页时重新进入公开页面。商业披露又被接入会话、权限和 Research API 的全局守卫；目标环境没有完整正文时，已登录客户会在披露页与产品入口之间循环，交易工作台实际不可达。

这两个问题把产品合同、身份授权和商业下单条件混成了同一个 Gate，也使 Client 复用了 Operations/Maintenance 的内部控制台视觉。

## 决策

- `/` 只属于公开 Riverton Capital 着陆页，不读取或渲染客户工作台。
- `/dashboard` 是登录后的稳定客户总览；Client 登录、品牌 Logo、面包屑和产品内返回入口均指向该路由。
- Client 使用独立客户交易 Shell。主导航只包含交易总览、交易大厅、模拟组合和会员；第二层包含策略实验室、AI 积分、绩效账单和资产服务。导航继续由有效权限投影过滤。
- `/workspace` 嵌入同一客户 Shell，不再加载第二套顶栏、侧栏或登录界面。
- 商业披露作为版本化商业合同保留。创建会员订单必须确认当前七份正文，订单服务继续失败关闭；披露不再作为登录、权限投影、Paper、行情、AI 工作区、通知、钱包只读或账户安全的全局 Gate。
- `/legal/consent` 保持独立可访问，账户菜单提供入口。披露确认事实与历史版本不可覆盖。
- 后端鉴权仍由 audience、会话、显式 RBAC assignment 和 data scope 决定；移除披露 Gate 不得扩大跨 audience 或跨客户数据范围。

## 结果

- 公开获客路径和客户产品路径不再争用 `/`。
- 登录后导航不会回到公开页面，也不会因内部工作区的独立会话请求闪现第二套登录页。
- 没有商业披露正文的环境仍可验收客户产品；只有创建新的付费订单时返回真实业务原因。
- 任何未来需要披露确认的动作必须按具体写接口列入作用域化策略，禁止重新引入“除白名单外全部阻断”的反向 Gate。
