# ADR-0020：实盘记账，以及把闸门收敛成一道有名字的

- 状态：已接受
- 日期：2026-08-23
- 关联：ADR-0019（执行服务与密钥托管）、迁移 0060–0062

## 背景

ADR-0019 文末记录了一个结论：实盘链路没有接通，被五处互相独立的检查各自挡住，
而比「发不出单」严重得多的是记账缺口——实盘成交不进仓位、不进风控、不进分成。

那份记录里同时留了一句判断：**那五处阻断逐个看都像 bug，逐个修都像在修 bug，
而全部修完之后打开的是一条记账不成立的真实交易通道。**

本次工作就是按那个判断的相反顺序做的：先补记账，再拆阻断。

## 决定

### 1. 模拟盘与实盘共用一本账，只多一个 book 维度

`official_paper_portfolios` 原本是一张**固定 10000 USDT 的模拟盘表**：CHECK、
触发器、以及域层的字面量类型 `principalUsdt: 10_000` 三处各钉一次。而 0053 的约束
要求 live 部署必须有 `paper_portfolio_id`——于是实盘部署只能指向一个本金写死的组合。

这是五条清单之外的第六处阻塞，也是最根本的一处。后果不是报错，是静默算错：
风控的百分比分母错了，分成的高水位线建立在虚构盈亏上。

**不另起一套并行的账。** 记账数学对两者完全一样，分叉成两套实现，分成口径迟早
也会分叉（INV-5）。改为加 `book` 维度：paper 恒 10000（模拟盘的**产品规则**，
让不同客户可横向比较），live 为客户真实投入。

「10000」从此只是模拟盘的产品规则，不再是记账规则。

部署 `mode` 与组合 `book` 的一致性交给数据库：`strategy_deployments` 增加生成列
`portfolio_book`（由 mode 推出），与组合的 book 组成外键。选生成列而不是普通列，
是因为「实盘部署指向模拟盘组合」恰恰是写入方自己不会发现的错误。

### 2. 事实由回执与对账归一得出，不引入第三张表

回执不可改写是对的——改写它等于销毁证据。但「不可改写」不等于「就是事实」：
对账存在的全部理由，就是下单响应可能是错的。

新增 `resolveEffectiveFill(回执, 对账记录)`，纯函数。刻意不加一张「修正后的回执」表：
三份记录只会让不一致多一种形态。

判定里三条是刻意的：
- 对账未决或已升级 → 事实未知，**什么都不记**。记成成交会凭空造出仓位，记成未成交
  会让引擎以为没有持仓而继续开新仓。两个方向都亏真钱（INV-7）。
- 升级件即使运维已确认仍算未决。「已确认」的含义是人看过了，不是事实已知。
- 状态是 resolved 却缺字段 → 未决，不退回回执。损坏时退回另一份记录会让损坏永远
  不被发现。

顺带补上一处会让平台多收钱的丢失：适配器一直返回手续费，对账 Worker 把它丢掉了。
回执停在 rejected 时费用是 0，而真实成交是收费的——这时对账是费用的唯一来源。
缺了它只能按 0 记账，方向是费用记少 → 净利记多 → 绩效分成多收。

### 3. 实盘成交落进账本（`lib/live-book-posting.ts`）

仓位、风控读数、绩效分成三者都读账本。三条阻塞不是三个 bug，是同一个缺口的三种
表现，补上这一条路三条同时消失。

其中一条值得单独记：**对账未决时停住整条队列，不跳过去记后面那笔。** 跳过会让账本
按错误顺序累计——一笔未决的买入后面跟着一笔卖出，先记卖出等于卖掉一个账上还不存在
的仓位。

### 4. 闸门收敛成一道，有名字

拆掉五处意外的 fail-closed：租约过滤 `exchange_account_id IS NULL`、边界断言、
`requestedPrice` 恒 null、symbol 格式（`BTCUSDT` vs `BTC/USDT`）、无创建入口。

现在实盘部署可以被租走、走完决策、记账、结算，唯一停下来的地方是下发订单之前的
`isLiveExecutionReady()`。

**闸门只有一道，并且有名字**——这正是为了不再靠意外来保证安全。

## 清单没有清空

`LIVE_EXECUTION_BLOCKERS` 换成了三条真的还没做的：

1. **`EXCHANGE_BALANCE_NOT_RECONCILED`** —— 平台的账本是交易所账户的影子账，
   没有任何机制核对两者是否还一致。客户手动交易一笔或提走一部分资金，账本就与真实
   持仓分叉，而分叉不报错。这是三条里最该先做的。
2. **`LIVE_ACTIVATION_ENTRY_MISSING`** —— `checkLiveActivation` 已把前置条件写成
   可穷举的判定（含 INV-11：带提现权限的 Key 一律拒绝），但没有客户侧入口调用它。
3. **`NEVER_EXECUTED_AGAINST_REAL_EXCHANGE`** —— 两家适配器的测试全跑在桩上。
   最小下单额、数量步进、价格精度、限流阈值只有真单才会暴露，而它们出错的方式包括
   「成交量与预期不符」，那会直接记错账。

## 更正

ADR-0019 与迁移 0053 里都写过「实盘沿用 paper 的记账路径，分成口径不分叉」。
方向是对的，但当时没看见本金被钉死在 10000——那句话在本次改动之前无法成立。
现在它成立了。
