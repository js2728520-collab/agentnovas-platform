# ADR-0024：产品参数冻结，以及由此改变的两处硬边界

状态：Accepted（产品范围）；实施与上线仍按能力受 Gate 约束

日期：2026-08-24

关联：PRD V3.0 第 15 节、ADR-0015（优盾充值专用通道）、ADR-0021、ADR-0022、G5

## 背景

PRD 第 15 节的 P-01–P-12 长期未决，阻断了多市场行情、计费、策略市场和资金相关的实施。
需求方于 2026-08-24 通过《AgentNovas V3 产品参数确认单》逐项答复，并在同日澄清了五处
歧义。参数现已全部冻结，唯一真源是
`packages/contracts/src/product-parameters.ts`。

大部分答复只是给既有设计填数字，不改变任何边界。但有两项**改变了此前由 ADR 固定下来的
硬边界**，因此需要本 ADR 明确记录，而不是让它们混在一次参数更新里悄悄生效。

## 决策

### 1. 平台服务余额提现纳入产品范围（改变 ADR-0015 的 deposit-only 边界）

ADR-0015 把优盾通道限定为「充值专用」，并写明「任何提现、代付、划转、自动扣款或退款
endpoint 均不实现、不加入 allowlist，也不出现在 UI」。需求方现确认要做提现，并明确
授权修改该约束。

**范围严格限定为平台服务余额**：客户此前充值进平台的 USDT 余额可以提回自己的地址。

**这与 INV-11 无关，INV-11 也不因此松动。** INV-11 管的是「平台永不持有客户**交易所
账户**的提现权限」——客户的交易所 API 密钥仍然只有读 + 交易权限，迁移 0045 的
`CHECK (withdrawal_authorized = 0 AND withdrawal_credential_ref IS NULL)` 保持原样。
两件事共用「提现」二字，但主体不同：一个是平台自己的余额账本，一个是客户在交易所的资产。
把它们混为一谈会得出完全错误的安全结论。

冻结的参数：

| 项 | 值 |
| --- | --- |
| 网络 | USDT-TRC20、USDT-ERC20、USDT-BEP20 |
| 单笔上限 | 10,000 USDT |
| 每日上限 | 100,000 USDT |
| 地址白名单 | 必须；新增地址 24 小时冷静期 |
| 复核 | maker/checker 双人 |
| 服务费 | 0%，链上手续费据实透传 |
| 费率调整 | 分公司总经理及以上发起，仍需另一人批准 |

最后一条是对确认单原文的收窄。确认单写的是「可以运营端设置，分公司总经理权限一级」；
资金相关变更按 INV-3 必须双人复核，因此该角色是**发起**费率变更的最低权限，不是可以
单人改价。这一点在实现时不可放宽。

**产品批准不等于可以出金。** 在 G5 全部通过前，资金出站接口继续固定拒绝：独立密钥域与
服务边界、地址白名单与冷静期、限额与风险筛查、服务费与账本状态机、链上确认与对账、
重放/错链/手续费不足/provider 故障演练，逐项都要有证据。任何部分完成都不开放资金出站。

### 2. 第 6 台设备改为自动挤出（收口 ADR-0022 的待确认项）

ADR-0022 把「第 6 台设备」列为待需求方确认的产品参数，当时的安全默认是拒绝登录。
需求方现确认改为：允许登录，自动踢掉最久未使用的那台。

这个选择的代价是被踢的人可能不知情。因此通知不是可选项：**被踢设备必须同时收到站内与
Email 安全通知**。没有通知的自动挤出会变成一个用户无法自查的账号安全盲区——攻击者登录
后悄悄把本人挤下线，本人只会以为「掉线了，重登一下」。

ADR-0022 的另一项待确认（异地精度）同时收口为：按 IP 网段变化判定，不引入 GeoLite2
或商业定位服务。

## 一处需要如实记录的差异

P-05 的客户策略上架回撤上限确认为按风险等级分档 10% / 15% / 20%，**高于**三张官方策略卡
自身的 6% / 10% / 15%。也就是说客户投稿的策略允许比平台自营策略更激进。这一点已在澄清
时向需求方指出并获确认，不是笔误，但它意味着策略广场的风险画像与官方卡不同，产品文案
不应让客户以为两者同一标准。

另外 P-05 取消了模拟盘时长要求，把关完全由人工审核承担。审核环节因此成为唯一的实质门槛，
其复核质量直接决定上架策略的风险水平。

## 后果

- P-01–P-12 全部冻结，G0 的参数项可以推进；但 G0 仍要求每个 Phase 有负责人与验收环境，
  且 P-12 确认为「不设日期、按 Gate 推进」，因此 G0 不因参数冻结而自动通过。
- 资金出站从「代码硬关闭」变为「产品已批准、Gate 未通过」。这是状态变化，不是能力开放；
  UI 与 API 在 G5 前必须显示真实 blocker，不得出现可产生出金请求的控件。
- ADR-0015 的 deposit-only 结论在「平台服务余额」范围内被本 ADR 取代；其余部分（验签、
  重放防护、双人复核入账、不生成假地址）继续有效。
- ADR-0022 的两项 provisional 参数收口，该 ADR 可从 Provisional 转为 Accepted。

## 不做

- 不放松 INV-11：平台永不持有客户交易所账户的提现权限，交易凭证不接受提现权限。
- 不授权自动扣款、自动退款或平台代客户转账。
- 不因产品批准而跳过 G5 的任何一项；未全部通过时资金出站接口固定拒绝。
- 不把「参数已冻结」表述为「Gate 已通过」或「可以发布」。
