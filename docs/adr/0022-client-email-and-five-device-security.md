# ADR-0022：Client 强制邮箱验证与五设备会话边界

状态：Provisional（核心安全合同已实现；第六设备策略与城市级定位待需求方确认）

日期：2026-08-23

关联：PRD V3.0 §5.1、ADR-0011、ADR-0021、迁移 0066

## 背景

V3 要求 Client 注册时同时提供国际手机号和邮箱，首期强制验证邮箱，同一账号最多并发
登录 5 台设备，并对新设备和异地登录发送提醒。当前基线已有邮箱 token、Session 列表和
单会话撤销，但注册允许占位邮箱，会话没有稳定设备身份，也没有并发设备上限或全量退出。

## 已实施决策

1. 新客户注册后保持 `pending`，24 小时验证 token 只以 SHA-256 摘要保存；邮件 outbox
   只保存 AES-GCM 加密 token。验证 URL 使用 fragment，避免 bearer token 进入代理日志。
2. 重发验证邮件使用邮箱和可信网络双桶限流，对不存在、已验证和待验证账号返回一致的
   公共响应；新 token 产生时旧的未使用 token 立即作废。
3. Client 浏览器获得独立的 256-bit、`HttpOnly`、`SameSite=Strict` 长期设备 Cookie；
   数据库只保存摘要。同设备重登会轮换旧 Session，不额外占用设备名额。
4. `client_complete_login_v3` 在锁定客户身份后原子计算设备数量。并发登录不能突破 5 台；
   Session、登录审计和安全通知 outbox 在同一事务提交。
5. 新设备产生站内和 Email 两条安全通知；已知设备跨 IP 网段时产生网络位置变化通知。
   页面只展示设备摘要与脱敏网络地址，不回显完整 user-agent 或 IP。
6. 用户可撤销一台非当前设备，也可一键撤销 Client 全部 Session（包括当前设备）；撤销
   使用当前 Session capability 绑定主体并记录原因和审计。

## 待需求方确认的产品参数

1. **第 6 台设备**：当前安全默认是拒绝新登录并提示先撤销旧设备；密码重置可在无法访问
   旧设备时撤销全部 Session。需求方需确认是否改为“登录时选择踢出某台设备”，禁止在未
   确认前静默挤掉最早设备。
2. **异地精度**：自托管 Nginx 当前没有可信城市数据库，当前以 IPv4 `/24`、IPv6 前缀
   变化作为网络位置变化证据。若必须显示城市/地区，需求方需在本地 GeoLite2 数据库和
   指定商业 IP 定位服务之间作出选择，并确认授权、更新、失败和隐私保留规则。

## 后果

- 邮件投递配置不完整时，注册身份和加密 outbox 事实仍保持一致，但用户无法完成验证；
  发布 Gate 必须验证真实 Email Worker 和回调，不得把“已排队”描述为“已送达”。
- 迁移不批量把历史 active 客户改成 pending。历史 active 但未验证邮箱的账号登录时被要求
  验证，并可通过同一非枚举重发入口恢复。
- G1 仍需四身份真实浏览器、多上下文 Session 撤销、邮件关闭降级和目标环境 Nginx 验收。
