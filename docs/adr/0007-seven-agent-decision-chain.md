# ADR-0007: 七智能体是确定性风控约束下的顺序决策链

## 状态

Accepted

## 日期

2026-08-20

## 背景

现有运行时保存七类事件，但角色为市场、技术、策略决策、反方、风控、执行、审计；客户说明书定义的七个产品职责则包含独立的策略研究员和 AI 最终决策官，审计是横切能力。当前交易大厅与会议页还混有静态结论，容易把演示内容误认为真实决策。

## 决策

1. 产品角色固定为市场分析师、技术分析师、策略研究员、反方审查员、首席风控官、AI 决策官、交易执行员。
2. 七阶段必须按序记录，并由唯一 `decisionRoundId` 关联；阶段可以退回、等待、拒绝或跳过执行，但不得静默缺失。
3. 指标、K 线完整性、仓位、风险、价格偏差、滑点、幂等和退出控制由确定性代码决定。
4. LLM 只能生成受限结构化解释和方案，不能修改已批准参数、调用密钥或越过风控。
5. 审计系统保存七阶段输入输出、版本和状态，但不是第七个 Agent。
6. 当前影子/模拟运行继续默认关闭真实订单；UI 必须显示执行环境。

## 迁移策略

- 旧 `audit` runtime event 保留为 legacy audit evidence，不伪装成 AI 决策官。
- 新决策轮增加独立 `final_decision` 事件；数据库允许读取旧事件和写入新事件。
- 客户 API 只返回脱敏、结构化的公开证据，不返回隐藏推理、密钥、私有端点或原始供应商 payload。
- 会议页从 API 恢复真实事件；无数据时显示空状态，不使用静态会议。

## 后果

- 运行时、合同、数据库迁移、UI 和测试需要同步修改。
- 研究 Agent 角色、运行时产品角色和运行时解释模型绑定必须分别命名，避免把“七个职责”理解成七个模型无限循环。
- 真实本地执行回执仍是未来独立切片；模拟订单意图不能标成客户交易所成交。
