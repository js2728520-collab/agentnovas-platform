### 1. 选定 AI 服务商并取得 API

策略生成对话需要一个兼容 OpenAI Chat Completions 格式的模型接口。你需要准备：

- API 请求地址，例如服务商提供的 `.../v1/chat/completions`
- API Key
- 模型名称
- 账户已充值并允许服务器所在地区访问

最终在 Cloudflare Worker 的“设置 → 变量和秘密”中配置：

| 变量名 | 类型 | 内容 |
| --- | --- | --- |
| `AI_API_URL` | 普通变量 | 完整 Chat Completions 请求地址 |
| `AI_MODEL` | 普通变量 | 服务商给出的模型 ID |
| `AI_API_KEY` | 加密秘密 | API Key，不得公开 |

验收：在“我的策略 → AI 策略生成”中提问，响应模式应显示为真实 AI 服务，而不是规则引导降级模式。

### 2. 取得历史行情与实时行情数据源

第一阶段可先用 Binance 公开 K 线接口做历史回测；为了稳定运行，建议另备一个付费或自建行情代理。你需要决定：

- 首个真实行情源：Binance 或 OKX
- 是否允许 Cloudflare 所在节点直接访问
- 是否需要购买商业行情套餐
- 新闻数据供应商（可以晚一阶段办理）

后台变量：

| 变量名 | 类型 | 内容 |
| --- | --- | --- |
| `MARKET_DATA_BASE_URL` | 普通变量 | 可选的 Binance 公共节点地址；留空使用内置多交易所适配器 |
| `MARKET_DATA_PROVIDER` | 普通变量 | 可选默认源：COINBASE、BINANCE、OKX、BYBIT、BITGET、GATE.IO、KUCOIN、KRAKEN |

验收：回测结果必须包含数据商、起止时间、K 线数量、手续费、滑点、交易样本和证据哈希。

### 3. 申请交易所模拟盘 API（先做 OKX，再扩八家）

你需要创建公司专用测试账户，不要使用个人主账户。第一家建议 OKX Demo Trading，准备：

- API Key
- Secret Key
- Passphrase（OKX 必填）
- 读取权限
- 交易权限
- 测试账户或模拟盘标识
- 固定 IP 白名单要求（若交易所支持）

随后再依次准备 Binance、Bybit、Bitget、Gate.io、KuCoin、Coinbase、Kraken。

注意：交易 API 与提现结算凭证必须分开保存、分开服务、分开审批。即使业务允许客户授权提现，也不能让普通交易执行进程直接持有提现权限。

### 4. 生成交易所凭证加密主密钥

系统不会明文保存客户交易所 API。你需要在本机密码管理器生成并保存一条高强度随机密钥，然后在 Cloudflare 设置：

| 变量名 | 类型 | 内容 |
| --- | --- | --- |
| `EXCHANGE_CREDENTIAL_ENCRYPTION_KEY` | 加密秘密 | 至少 32 字节随机值 |

该值丢失后，已经加密的交易所凭证将无法解密；泄露后必须轮换全部客户凭证。

### 5. 准备通知渠道账号

你需要办理：

### 6. 准备链上收款信息

## 五、目前后台已经打通的闭环

### 策略创作闭环

`专业对话引导 → 结构化参数 → 保存版本 → 可选历史回测/模拟测试 → 提交人工审核 → 双人审核 → 上架策略广场`

关键约束：

- 用户不能自己填写收益、胜率、回撤来冒充平台回测。
- 每次修改策略都会产生新版本，旧版本的回测报告只作为历史资料，不复制到新版本。
- 回测必须由服务端拉取历史 K 线，并计入手续费与滑点。
- 模拟测试只统计带策略编号、决策编号且已经平仓的模拟订单。
- 回测与模拟测试均为作者可选的研究工具，不设置“通过/不通过”，也不阻止保存或提交审核。
- 人工审核根据策略内容、风险边界和披露完整度作出决定，不要求任何验证器记录。
- 审核通过前不能被其他客户跟随。

### 跟随与模拟执行闭环

`选择已上架策略 → 选择本人模拟账户 → 会员检查 → API 权限检查 → 风控检查 → 激活订阅 → 生成决策编号 → 模拟下单 → 成交同步 → 平仓 → 收益归因 → 审计归档`

关键约束：

- 只能选择属于当前客户且已经通过读取、交易权限检查的账户。
- 首阶段仅允许模拟盘，不能误入真实账户。
- 每笔订单保存策略 ID、策略版本、订阅 ID、决策 ID、账户 ID 和成交结果。
- 客户独立手动订单没有平台决策 ID，不进入平台收益和佣金统计。

现在已经增加服务端自动模拟运行入口，并支持两级执行模式：

`POST /api/automation/demo-cycle`

- 默认：站内可审计模拟成交，不向交易所发送订单。
- 可选：完成验收后设置 `OKX_DEMO_EXECUTION_ENABLED=true`，改为向 OKX Demo 发送现货市价单，并同步订单编号、成交数量、均价、手续费和状态。
- 两种模式都只接受 `demo` 账户；当前执行器没有实盘参数，也不会向 OKX 实盘环境发单。
- OKX Demo 尚未成交的订单保存为 `submitted`/`closing`，下一轮先同步回执，未完成前不会重复开仓或把挂单误算成收益。

每轮处理活跃跟随关系，读取策略当前版本和完整K线，使用与回测一致的 EMA、RSI 或通道规则生成入场、退出或观望结论，然后执行：

`完整K线 → 确定性信号 → 会员与催收检查 → API权限检查 → 行情健康检查 → 单日亏损限制 → 仓位限制 → 决策编号 → 模拟成交/平仓 → 收益归因 → 审计记录`

安全约束：

- 自动入口必须携带 `x-automation-key`，对应 Cloudflare 加密秘密 `AUTOMATION_INTERNAL_SECRET`。
- 密钥应至少 24 个字符并与其他密钥完全不同。
- 同一根完整K线只处理一次，避免调度重复造成重复下单。
- 只处理 `demo` 账户；当前代码不会向实盘账户发送订单。
- 平台紧急停止、会员失效或催收停开仓时仍检查已有仓位退出，但拒绝新开仓。
- 没有信号时记录观望证据，不生成虚构交易。
- 上线后需要用 Cloudflare 工作流、Cron Worker 或可信调度服务按策略最小周期调用该入口；首期建议每 5 分钟一次。

### 上架与作者收益闭环

`平台收到客户绩效分成 → 平台收入确认 → 50% 平台费用 → 50% 作者应得 → 每月锁定 → 双人财务审核 → 5 日人工付款`

没有实际收到客户分成时，不生成作者可结算收入，也不生成组织业绩。
