# AgentNovas 全平台 V3 验收与发布 Gate

状态：`TARGET`
日期：2026-08-23
上位真源：PRD V3.0、ADR-0021

## 1. Gate 原则

- Gate 优先于日期、演示效果和功能开关。
- 每个高风险能力独立解锁；真实现货通过不代表永续、提现或自动部署通过。
- `TARGET/BLOCKED` 不能因页面存在、环境变量存在或桩测试通过而改成 `CURRENT`。
- 所有证据必须绑定 commit、制品 SHA-256、migration registry 和测试环境。
- 未知外部结果一律失败关闭，不显示成功。

## 2. 全阶段共同 Gate

每个阶段退出前必须通过：

- 需求/Spec/API/数据模型/状态机同步。
- 中央 API Policy 零遗漏。
- 单元、合同、PostgreSQL、安全和错误路径测试。
- TypeScript、lint、三端 production build 和 `git diff --check`。
- 320/768/1024/1440、键盘、axe、console/network 浏览器验收。
- 日志、响应、导出和构建产物 secret/PII 扫描。
- 数据迁移 fresh/rerun/concurrent/N-1/backup-restore 证据。
- Runbook、监控、告警、回滚和负责人。

## 3. G0：文档与产品参数 Gate

- [ ] PRD 第 15 节全部产品参数冻结或明确分期。
- [ ] MetaMask、外汇/贵金属、股票行情供应商边界明确。
- [ ] 套餐、Credits、跟单收费、作者分账和退款形成版本化合同。
- [ ] 提现/划转的资金和服务费规则单独获批。
- [ ] 每个 Phase 有负责人、依赖、验收环境和退出日期。

G0 不通过时可以做无风险基础设施，但不能承诺对应业务发布日期。

## 4. G1：身份、权限与注册链接 Gate

- [ ] Operations 页面不再展示组织架构树或关系编辑入口。
- [ ] scope resolver 仍正确使用后端组织/分公司事实。
- [ ] 角色链接不能越级、不能静默改角色、只存 token 摘要。
- [ ] 注册事务原子创建身份、published assignment、scope 和审计。
- [ ] 撤销/重生成、泄露响应、限流、MFA 和 Session 撤销通过并发测试。
- [ ] 客户邀请和内部角色链接不可互换。
- [x] Client 邮箱/国际手机号必填、验证 token 摘要和加密 outbox 通过 PostgreSQL 测试。
- [x] Client 五设备上限、同设备轮换、并发第 5/6 台和全量撤销通过 PostgreSQL 测试。
- [ ] Client 新设备/网段变化提醒完成真实 Email 和多浏览器上下文验收。

G1 仍为未通过：本节已有自动化证据和云端 Docker `nginx -t` 不替代第 2 节要求的四身份
真实浏览器与真实邮件验收；ADR-0022 的两个产品参数也仍待需求方确认。

## 5. G2：行情与多市场 Gate

- [ ] 每市场有合法主备供应商、授权和成本确认。
- [ ] symbol、时区、交易日历、公司行动和 K 线周期正确。
- [ ] WebSocket 延迟、乱序、断线、重连、补齐和 stale 判定通过压测。
- [ ] 主备源切换验证价格偏差和序列完整性。
- [ ] 陈旧行情不会驱动新开仓。
- [ ] 页面准确显示来源、延迟、时间和连接状态。

## 6. G3：AI、策略市场与收费 Gate

- [ ] QuantDinger 参考版本和移植清单冻结。
- [ ] DSL、回测、模拟盘时长、回撤/收益和稳定性门槛版本化。
- [ ] 投稿、审核、上架、下架和重大版本重审状态机通过。
- [ ] 作者、平台、客户费用合同和退款规则不可变快照。
- [ ] 跟单参数、用户确认、停止和风险阻断端到端通过。
- [ ] LLM 无法直接下单或绕过风险 Gate。

## 7. G4：真实交易共同 Gate

- [ ] Execution Service 是唯一长期持有交易凭证解密能力的进程。
- [ ] Web/Worker 构建不含凭证加解密密钥或服务端私有模块。
- [ ] provider adapter 完成签名、时钟、精度、限流、幂等、部分成交和查单。
- [ ] 余额/持仓与 live book 对账可持续运行。
- [ ] 客户 live activation 记录包含账户、产品、策略、风险和披露版本。
- [ ] `reconcile_wait`、人工升级、账户阻断和安全平仓通过故障注入。
- [ ] provider/account/strategy kill switch 和恢复演练通过。
- [ ] Paper、Demo、Live 账本、回执和 UI 不混写。

## 8. G4A：真实现货 Gate

每家交易所逐独立环境通过：最小额真实单、撤单、部分成交、超时后查单、手续费、精度、账户手动交易后再对账、连接中断和熔断。

只有单个 `(provider, production, spot)` 授权记录可打开该组合；不得使用全局布尔开关。

## 9. G4B：USDT 永续 Gate

在 G4A 之外必须通过：

- [ ] 杠杆、保证金模式、position mode、reduce-only 和 liquidation 字段。
- [ ] funding、标记价格、强平风险和 ADL 处理。
- [ ] 合约规格、最小数量、面值、精度和风险限额。
- [ ] 永续与现货账户/仓位/费用/绩效不混账。
- [ ] 极端行情、穿仓和交易所自动减仓事故演练。

仓库规则仍要求真实永续保持关闭；只有项目规则和专项 ADR 经明确授权更新后才可进入实施。

## 10. G5：提现、划转与服务费 Gate

- [ ] 与交易凭证完全不同的密钥域和服务边界。
- [ ] 地址白名单、冷静期、限额、风险筛查和 maker/checker。
- [ ] 服务费、退款、失败、链上确认和对账状态机。
- [ ] 热/冷钱包或第三方托管责任、灾备和保险/责任边界明确。
- [ ] 重放、错链、地址污染、手续费不足和 provider 故障演练。
- [ ] 账本、客户余额和链上事实一致。

任一项未完成时资金出站 endpoint 不存在或固定拒绝。

## 11. G6：Operations 与 Maintenance Gate

- [ ] PII 字段级权限覆盖列表、详情、计数和导出。
- [ ] 高风险交易干预准确区分审批、接受和执行结果。
- [ ] Token、套餐、价格、Prompt、技能和开关版本化双审。
- [ ] Maintenance 响应无客户业务信息、secret 和完整 endpoint。
- [ ] 日志、任务、WAF/IP 和审计状态准确。

## 12. G7：CI/CD 控制面 Gate

- [ ] 只能调用固定仓库、固定 workflow、固定动作和不可变制品。
- [ ] Maintenance 不持有长期 CI token，不接受任意 Shell/SSH/SQL/ref。
- [ ] production 需要同制品 staging 成功和不同人员批准。
- [ ] 回调签名、幂等、乱序和失败不切 current 通过测试。
- [ ] 回滚目标是同环境历史成功版本，数据库兼容已验证。
- [ ] 控制面失陷时的权限撤销、审计和应急停止演练通过。

## 13. G8：体验与正式发布 Gate

- [ ] 六套主题和图表/Logo/状态色完整。
- [ ] 默认英语、浏览器/地区推断和偏好持久化正确。
- [ ] SEO、性能预算、无障碍和四断点通过。
- [ ] 域名、Cookie、CORS、邮件、TLS 和回跳全部冻结。
- [ ] 运营、运维、事故、客服、退款和争议 Runbook 完成演练。
- [ ] 发布评审明确本次只打开哪些 provider/product/capability。

## 14. 绝对否决项

出现以下任一情况立即停止发布：

- Secret、客户凭证、完整私有 endpoint 或非授权 PII 泄露。
- 跨 audience、跨 scope 或撤权后重新授权。
- 未知订单被当作未下单或已成交。
- Paper/Demo 被展示为客户真实成交。
- 提现权限进入交易执行服务。
- 无 staging 同制品证据的 production 部署。
- 数据迁移、账本、对账或回滚无法复现。
