# AgentNovas 完整三端平台 V3 功能说明

状态：`TARGET`；需求范围已确认，实施状态见任务看板
版本：3.0
日期：2026-08-23

## 1. 用途

本文把 `PRD.md` 转换为跨产品、研发、运营、运维和 QA 可共同理解的功能视图。PRD 决定“做什么”，专项 Spec 决定“如何约束”，任务看板决定“何时实施”。

当前已部署系统仍是受控 Beta/Paper 基线。本文出现的真实交易、提现、划转和部署触发能力均为目标，不是当前上线证明。

## 2. 产品组成

### 2.1 Client

面向交易客户，覆盖公开入口、注册登录、行情、AI 助手、交易大厅、策略广场、策略跟随、交易中心、会员、Credits、消息和账户安全。

### 2.2 Operations

面向员工和五级业务管理角色，覆盖客户、账户、交易、风控、报表、权限注册链接、运营账号、审批和业务审计。Operations 不展示组织架构页面。

### 2.3 Maintenance

面向技术、运维、安全和产品配置角色，覆盖系统与品牌、模型、技能、Prompt、Token、套餐、支付、优惠、外部集成、日志、安全、版本和 CI/CD 控制面。Maintenance 不展示客户业务信息。

## 3. 公开入口、注册与会话

- 公开着陆页与登录后的客户总览分离。
- Client 注册要求国际手机号和邮箱，首期验证邮箱、收集但不验证手机号。
- Client 同时最多 5 台设备登录；新设备和异地登录提醒，支持退出全部设备。
- 客户邀请链接可长期重复使用并可重生成。
- 内部账号使用角色/权限注册链接自助注册，不由上级逐人创建。
- 内部链接长期可重复使用，手动作废；重生成立即撤销旧链接。
- 注册成功立即得到链接对应权限，无人工审批；MFA、会话安全和高风险审批仍然有效。

## 4. Operations 权限模型

五级角色为员工、主管、经理、分公司总经理、总公司总经理。上级只能生成低于自身层级的注册链接。

Operations 不显示组织树。后端保留分公司、角色归属、客户归属和数据范围：

- `SELF`
- `DIRECT_REPORTS`
- `TEAM_TREE`
- `ORGANIZATION`
- `ORGANIZATION_SET`
- `PLATFORM`

客户手机号、完整邮箱、IP、设备、社交联系方式、充值消费、交易账户和持仓采用字段级权限。列表、详情和导出使用同一授权与脱敏规则。

## 5. 行情中心

- 加密货币、A 股、港股、韩股、日股、外汇和贵金属进入目标市场范围。
- 用户可以让行情源跟随交易账户，也可以独立选择；每个策略可以使用不同数据源。
- 加密货币无账户配置时默认 Coinbase。
- 每个市场配置主备源；统一的是降级状态机，不是统一供应商。
- WebSocket 端到端延迟目标 ≤ 500ms，断线恢复目标 ≤ 10 秒。
- 界面显示来源、更新时间、延迟和连接状态。
- 陈旧缓存只展示，不能驱动自动订单；行情不可信时停止新开仓。
- A 股和港股优先，韩股和日股随后扩展；均需指数、热门股、全市场搜索、完整 K 线和实时行情。

## 6. AI 助手与策略生成

- 原 Agent 对话统一为 AI 助手。
- 以 QuantDinger 指定代码和演示为移植基准。
- 移除观察名单、分析标的选择和原默认 8 卡片。
- 支持普通对话、文字建议、可编辑参数和可回测结构化策略。
- 结构化策略必须通过 DSL 校验、回测、准入和风控；LLM 不拥有最终执行权。
- 进入实盘前由客户确认策略版本、参数、账户、费用和风险。

## 7. 交易大厅与工作记录

- 七智能体/AI 决策使用对话气泡展示。
- Agent 列表和决策轮均可进入详情。
- 详情包含完整对话、策略版本、行情快照、风控、订单/成交和审计。
- 工作记录至少保留 6 个月；授权 Maintenance 人员可脱敏导出。
- Paper、Demo、Live 使用不同 book 和状态文案，不得混写成交或收益。

## 8. 策略广场与跟单

策略广场提供浏览、筛选、卡片、详情、投稿和跟单。

发布状态：

`DRAFT → SUBMITTED → UNDER_REVIEW → APPROVED → LISTED → DELISTED`

上架要求历史回测、规定模拟盘时长、收益/回撤门槛、人工审核、风险披露；重大版本重新审核。

跟单至少配置账户、投入金额、最大仓位、止盈止损、杠杆和最大亏损。跟单支持固定订阅、收益分成和作者/平台分账。客户、授权风控角色、自动风控和全局熔断均可停止异常策略。

## 9. 真实交易与执行

首期目标交易所为 Binance、OKX、Coinbase、Crypto.com、Kraken；MetaMask 作为独立钱包集成。Bybit、Bitget、Gate.io、HTX 为后续候选。

目标产品覆盖加密货币现货、USDT 永续、外汇和贵金属。每个 provider 独立完成签名、精度、限流、幂等、部分成交、查单、对账和故障恢复。

客户交易凭证服务端加密保存，只允许只读和交易权限并要求 IP 白名单。执行服务是唯一长期持有解密能力并签名订单的进程。任何带提现权限的交易凭证不得被交易执行服务接受。

真实订单在余额/持仓对账、客户激活入口和真实交易所最小额 smoke 等 blocker 清零前保持失败关闭。

## 10. 提现、划转和资金

提现、划转与服务费是已确认目标，但不是交易 API 的附带能力。它们必须独立设计币种/网络、托管责任、限额、地址白名单、延迟、服务费、审批、退款、账本、对账和事故响应。

在专项决策、合规、安全和真实环境 Gate 通过前，资金出站 API 不存在或固定拒绝。

## 11. 会员、Credits、支付与优惠

- 月、季、年和终身套餐，以 USDT 计价。
- 终身会员不等于无限 Credits 或无限增值服务。
- 价格、权益、Credits、费用和生效时间版本化，历史订单保留快照。
- AI Credits 首期按每次对话固定扣减；具体数值待产品冻结。
- 退款原则上不退；例外由人工审核并退回原渠道。
- 优惠码、折扣码和优惠券支持有效期、次数、套餐、用户/组织范围、叠加与退款恢复。

## 12. Operations 业务功能

- 客户搜索、筛选、列表、详情、归属、冻结/解冻和审计。
- 查看券商/交易所账户类型、连接、余额、持仓和 API 状态，但永不读取 Secret。
- 默认只读交易数据；撤单、平仓、暂停策略和冻结交易只向受控风控角色开放。
- 风险参数修改和熔断解除需要更高权限与审批。
- 看板支持用户/组织、标的/策略、订单状态、时间、交易所、净盈亏和财务指标。
- CSV/Excel 导出沿用在线字段和数据范围权限。
- 账号停用可恢复，历史事实不删除。

## 13. Maintenance 技术功能

- 品牌、域名、协议、多语言和预览。
- 模块、用户/组织、版本、百分比和定时功能开关。
- 模型供应商、Profile、Agent 绑定、技能和 Prompt 版本。
- 草稿编辑、测试、双人审批、定时发布和回滚。
- Token 用量按用户、组织、模型、Agent、日期、功能、费用和失败率查询。
- 套餐、Credits、USDT 支付、人工退款和优惠规则版本化管理。
- 券商、行情、支付、通知和安全集成只展示安全状态，不回显密钥。
- API、登录、Worker、交易、风控、模型、支付和数据库任务日志。
- 应用、Nginx、WAF/防火墙多层安全控制。
- 通过受限 CI/CD 工作流触发部署和回滚；浏览器不执行任意基础设施命令。

## 14. 主题、语言与体验

- 三套浅色、三套深色主题。
- 默认英语；已保存偏好优先，其次浏览器/地区推断，最后英语。
- 公开页、认证页、错误页和邮件链接语言一致。
- 覆盖 320/768/1024/1440、键盘、焦点、语义、错误提示、SEO 和性能预算。

## 15. 状态真实性与审计

- `configured`、`enabled`、`connected`、`alive`、`healthy`、`stale`、`accepted`、`filled` 和 `failed` 不能混用。
- 未知结果不得显示成功。
- 登录、权限链接、角色、敏感字段、客户冻结、交易干预、策略发布、跟单、订单、资金、定价、Prompt、开关和发布均审计。
- 真实订单、账本和收费事实不可物理删除或覆盖。

## 16. 当前基线与主要差距

当前已有：三端隔离、RBAC、受控 Beta/Paper、Demo、会员/Credits/账本、执行服务、凭证隔离、对账和 live book 基础。

主要差距：

- 角色权限注册链接与隐藏组织架构页面的迁移。
- 多市场实时行情与供应商授权。
- 客户策略市场、作者合同和收费。
- 五家首期交易所及 MetaMask 的正式适配范围。
- 实盘 blocker、真实交易所验收和逐 provider 灰度。
- 提现/划转独立资金产品。
- Maintenance 的完整产品配置和 CI/CD 触发控制面。
- 六套主题、完整 i18n 和新的验收矩阵。
