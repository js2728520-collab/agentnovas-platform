# Client 应用规格

## 1. 目标

Client 为客户提供策略研究、七智能体交易大厅、历史回测、模拟/影子运行、策略广场、交易所连接、会员、平台服务钱包和通知。首版保留多语言与现有深色机构视觉，不进行无关重写。

## 2. 导航与注册

- Client 支持登录、邀请注册、忘记密码和退出。
- 普通客户导航不得出现旧“运营后台”入口。
- 客户页面不能通过前端角色判断读取 Operations/Maintenance API。
- `/wallet`、`/wallet/deposits`、`/notifications` 为稳定路由；交易大厅和策略工作区在后续拆分时应获得独立稳定 URL。

## 3. 交易大厅

### 页面结构

1. 产品边界条：交易池、现货目标、当前执行环境、真实订单开关、数据时间。
2. 三张官方策略卡：独立状态、版本、仓位、最近决策与样本口径。
3. 七角色工作区：角色职责、当前阶段、最近公开结论和数据时间。
4. 决策轮列表：按 `decisionRoundId` 查询成交与未成交记录。
5. 决策轮详情：七阶段时间线、版本、证据摘要、风险和执行回执。
6. 客户控制区：模拟/影子只读；未来真实跟随才显示暂停新开仓、仅许平仓、停止跟随和解除连接。

### 禁止状态

- 不显示硬编码 BTC 价格、市场风险、交易所、收益或静态会议为实时数据。
- API 无数据时不使用 fallback 策略业绩。
- 没有真实客户控制接口时不显示无行为的“紧急停止”。
- 当前只有模拟订单意图时，不能写“已在用户交易所执行”。

### 七角色

角色、输出、风险参数和流程以 `../product/SEVEN_AGENT_TRADING_HALL.md` 为准。前端角色卡和会议时间线使用 `packages/contracts` 的固定目录，禁止组件各自硬编码另一套角色名。

### 状态

| 状态 | 客户文案 |
| --- | --- |
| `monitoring` | 监控中，未形成候选机会 |
| `awaiting_data` | 等待完整数据 |
| `needs_revision` | 反方要求修改 |
| `risk_rejected` | 风控拒绝新开仓 |
| `waiting` | AI 决策官暂缓 |
| `approved_shadow` | 已批准，仅影子记录 |
| `approved_paper` | 已批准，进入模拟执行 |
| `execution_skipped` | 本地条件不合格，已跳过 |
| `paper_filled` | 模拟成交，不代表真实成交 |

## 4. 策略与研究

- “创建策略”继续使用可恢复的多 Agent 研发流水线，不增加第二套对话。
- 用户自建策略的 1x 永续研究/回测与三张官方现货策略卡是两个产品合同。
- 快速模式永久限制为模拟；只有标准/深度通过版本可申请策略广场审核。
- 分享、上架和真实资格是不同状态，不因回测通过自动连锁执行。

## 5. 交易所连接

- 客户只在未来真实跟随时需要连接交易所。
- 权限必须检查“读取 + 交易、无提现”；完整 Secret/Passphrase 永不回显。
- 固定 IP 未配置时明确显示未配置。
- 当前适配器未完成的交易所显示“规划/待接入”，不能让连接表单制造成功。

## 6. 平台服务钱包

- 钱包显示可用/冻结余额和不可变流水。
- 充值只为会员与 AI 服务，不作为策略资金。
- 服务商未配置时创建订单返回 503，页面不显示虚假地址、二维码或确认数。
- 金额、币种、网络、资金状态、风险状态和订单状态分别展示。

## 7. 通知

- 通知中心整合收件箱、已读、渠道绑定和偏好。
- 安全通知可以明确标为不可关闭。
- 动态结果使用 `aria-live`；保存失败保留原值。
- `configured_not_sent` 显示“已配置但未发送”。

## 8. 可访问性与响应式

- 320/768/1024/1440 四档通过。
- 数据表在窄屏使用卡片或有标题的受控横向滚动。
- 对话框焦点约束并在关闭后回到触发按钮。
- 所有表单有 label；状态不只依赖颜色；动态状态可被辅助技术读取。

## 9. 核心验收

- 七角色数量、名称、顺序与说明书一致。
- 决策轮无数据、部分事件、完整事件、风险拒绝和模拟执行均有正确页面状态。
- 官方策略卡不展示永续/做空/杠杆入口。
- 真实订单开关关闭时无法从 Client 触发任何真实订单。
- 服务钱包和交易所策略资金在所有文案中明确分离。
